5. 3D PCDからNav2用2Dマップを作る

最初に理解すること: Nav2用PGMで 白=Free、黒=Occupied、灰=Unknown。 「ほぼグレー」は、床を障害物として認識したというより、 各2Dセルが観測済みと判定されていない場合に起こりやすい。

5.1 まず公式スクリプトで作る

ros2 run lidar_localization_ros2 generate_occupancy_map_from_pcd.py \
  --pcd ~/ros2_ws/src/lidar_localization_ros2/map/atr_out_points.pcd \
  --output-dir ~/ros2_ws/src/lidar_localization_ros2/map/nav2 \
  --map-name atr_nav2 \
  --resolution 0.20

生成物:

atr_nav2.pgm
atr_nav2.yaml
atr_nav2_stats.json

5.2 グレーが多い場合はstatsを見る

cat ~/ros2_ws/src/lidar_localization_ros2/map/nav2/atr_nav2_stats.json

主に確認する値:

observed_cell_count
free_cell_count
occupied_cell_count
unknown_cell_count
min_points_per_cell
resolution_m

unknown_cell_count が非常に多い場合は、最初に resolutionとmin-points-per-cell を疑う。

5.3 原因切り分け

試験目的
resolution 0.10 → 0.201セルを大きくして点密度を上げる
min-points-per-cell 2 → 1疎なPCDでも観測済みにする
CloudCompareで床点を確認床そのものがPCDに十分存在するか確認
# 診断用。最終設定とは限らない。
ros2 run lidar_localization_ros2 generate_occupancy_map_from_pcd.py \
  --pcd ~/ros2_ws/src/lidar_localization_ros2/map/atr_out_points.pcd \
  --output-dir ~/ros2_ws/src/lidar_localization_ros2/map/nav2 \
  --map-name atr_nav2_diag \
  --resolution 0.20 \
  --min-points-per-cell 1
min-points-per-cell=1 はノイズも観測済み扱いしやすい。 まず原因確認用として使い、その後に点群品質とresolutionを見て調整する。

5.4 なぜ単純なXY投影だけでは不足するか

公式変換スクリプトは、reference trajectoryを使わない場合、 各XYセルの max_z - min_z を見て障害物判定する。 これは平坦な1フロアには簡単で便利だが、次では弱い。

  • GLIM PCDの床点が疎い
  • 傾斜・スロープ
  • 階段
  • 上下階が同じXYに重なる建物
平坦床:
max_z - min_z ≒ 0
→ Free

壁:
max_z - min_z が大きい
→ Occupied

スロープ:
隣接セルごとに床Zが変化する
→ XY投影だけでは「歩ける傾斜」の判断ができない

5.5 改善版: 床面・傾斜を考慮した2D map生成

この資料には次の補助スクリプトを同梱している。

tools/generate_floor_aware_occupancy_map.py

処理:

3D PCD
  ↓
XYセル化
  ↓
各セルの低いZを「局所床高」として推定
  ↓
近傍で床高を平滑化
  ↓
隣接床高から slope を計算
  ↓
床より一定高さ上の点 → 障害物
急傾斜                 → 障害物
連続した緩傾斜         → Free
観測不足               → Unknown

依存

sudo apt update
sudo apt install -y python3-open3d python3-numpy python3-pil

実行例

python3 tools/generate_floor_aware_occupancy_map.py \
  --pcd ~/ros2_ws/src/lidar_localization_ros2/map/atr_out_points.pcd \
  --output-dir ~/ros2_ws/src/lidar_localization_ros2/map/nav2_floor \
  --map-name atr_floor \
  --resolution 0.20 \
  --min-points-per-cell 1 \
  --obstacle-height-m 0.35 \
  --max-traversable-slope-deg 18 \
  --inflate-radius-m 0.35

追加生成:

atr_floor.pgm
atr_floor.yaml
atr_floor_stats.json
atr_floor_slope_debug.pgm
slope_debug: 床高の局所変化を見るための確認画像。 傾斜閾値を決めるときに使う。Nav2へ直接読ませる画像ではない。

5.6 傾斜・スロープの扱い

2D Nav2ではZ方向の姿勢制御は行わない。 「そのXY領域を通ってよいか」を2D地図で表現し、 実際のPitch/Rollへの追従は4足/ヒューマノイドの歩行制御へ任せる。

地形2D map将来拡張
平坦Free通常速度
緩い坂FreeSpeedFilterで低速化
急坂Occupied / KeepoutTraversability評価
階段通常Nav2では通行不可専用Stair Behavior

--max-traversable-slope-deg はロボットの実能力に合わせる。 18°はサンプル値であり、実機試験で決める。

5.7 階段・複数階

複数階を1枚のOccupancyGridへ潰さない。 1Fと2Fが同じXYに重なるため、2Dでは区別できない。

推奨:

3D Localization map:
  building_all.pcd
  → 建物全体で1つでもよい

Nav2 2D maps:
  floor1.yaml + floor1.pgm
  floor2.yaml + floor2.pgm
  floor3.yaml + floor3.pgm

Z sliceで各階を作る例

# 例: 1F周辺だけを使う
python3 tools/generate_floor_aware_occupancy_map.py \
  --pcd ~/ros2_ws/src/lidar_localization_ros2/map/atr_out_points.pcd \
  --output-dir ~/ros2_ws/src/lidar_localization_ros2/map/floor1 \
  --map-name floor1 \
  --resolution 0.20 \
  --z-min -0.5 \
  --z-max 2.2

# 2Fは建物の実Zに合わせて変更
python3 tools/generate_floor_aware_occupancy_map.py \
  --pcd ~/ros2_ws/src/lidar_localization_ros2/map/atr_out_points.pcd \
  --output-dir ~/ros2_ws/src/lidar_localization_ros2/map/floor2 \
  --map-name floor2 \
  --resolution 0.20 \
  --z-min 3.0 \
  --z-max 5.7
Z値は例。CloudCompareやGLIM viewerで各階の実際のZ範囲を確認して決める。
