4. lidar_localization_ros2 セットアップ

この環境で確認された重要事項: upstream の現行 CMakeLists.txt のままではビルドできず、同梱の 動作確認済み CMakeLists.txt に置き換えることでビルドできた。したがって本資料では、この差分を既知のビルド問題として扱う。

4.1 問題の本質: ndt_omp_ros2 のリンク方法

問題箇所は、optional pybind11 backend g2_ndt_score のリンク。 upstream 側は legacy-style の変数を参照している:

target_include_directories(g2_ndt_score PRIVATE
  include
  ${PCL_INCLUDE_DIRS}
  ${ndt_omp_ros2_INCLUDE_DIRS})

target_link_libraries(g2_ndt_score PRIVATE
  ${ndt_omp_ros2_LIBRARIES}
  ${PCL_LIBRARIES})

一方、この環境でビルド成功したCMakeは export済みCMake targetを直接リンクする:

target_include_directories(g2_ndt_score PRIVATE
  include
  ${PCL_INCLUDE_DIRS}
)

target_link_libraries(g2_ndt_score PRIVATE
  ndt_omp_ros2::ndt_omp
  ${PCL_LIBRARIES}
)
なぜこちらが妥当か: ndt_omp_ros2 自身は ndt_omp libraryを install(... EXPORT export_ndt_omp ...) し、 ament_export_targets(export_ndt_omp HAS_LIBRARY_TARGET) でexportしている。 一方、ndt_omp_ros2_LIBRARIES / ndt_omp_ros2_INCLUDE_DIRS のような legacy変数を明示的にexportする構成ではない。このため、consumer側ではexport target ndt_omp_ros2::ndt_omp を使う方が確実。

4.2 添付CMakeの扱い

この資料一式には、実際にビルド成功したCMakeをそのまま保存している。

fix/CMakeLists.txt
fix/ndt_omp_target_link_fix.patch

既存ファイルをバックアップして置き換える場合:

cd ~/ros2_ws/src/lidar_localization_ros2

cp CMakeLists.txt CMakeLists.txt.original
cp /path/to/guide/fix/CMakeLists.txt CMakeLists.txt

上流CMakeへの変更を最小限にしたい場合は、同梱patchの g2_ndt_score 部分だけを適用する。

4.3 Clone / dependency

source /opt/ros/humble/setup.bash

cd ~/ros2_ws/src
git clone https://github.com/rsasaki0109/lidar_localization_ros2.git

cd ~/ros2_ws
rosdep install --from-paths src --ignore-src -r -y

4.4 修正版CMakeでクリーンビルド

cd ~/ros2_ws

rm -rf \
  build/lidar_localization_ros2 \
  install/lidar_localization_ros2

source /opt/ros/humble/setup.bash

colcon build \
  --symlink-install \
  --packages-select lidar_localization_ros2 \
  --event-handlers console_direct+

source install/setup.bash

4.5 ビルド後確認

ros2 pkg prefix lidar_localization_ros2

ls -l \
  ~/ros2_ws/install/lidar_localization_ros2/share/lidar_localization_ros2/local_setup.*

ros2 pkg executables lidar_localization_ros2
ここでの整理: ament_package() は添付版にもupstream版にも存在するため、 今回の主原因は「ament package化されていないこと」ではない。 ndt_omp_ros2をlegacy変数経由でリンクしていたconsumer側CMakeが問題で、 namespaced imported targetへ変更したことで解消した、と整理する。

4.6 optional backendとの関係

この問題箇所は次の条件内にある:

if(pybind11_FOUND AND Python3_Development.Module_FOUND)
  ...
  pybind11_add_module(g2_ndt_score ...)
  ...
endif()

そのため、pybind11 / Python Development.Moduleが見つからない環境では g2_ndt_score 自体がbuildされず、問題が表面化しない場合がある。 逆に必要依存が揃った環境ほど、このリンク不備に到達する。
