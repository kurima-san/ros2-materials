14. Docker環境の作成・配布

4構成を同梱: MID-360、GLIM、lidar_localization_ros2をそれぞれ独立してbuildできる構成と、3機能を収録したオールインワンイメージを用意した。オールインワンでも実行時は「センサー＋GLIM」または「センサー＋Localization」を選ぶ。

14.1 構成を選ぶ

用途場所イメージ
MID-360センサー単体docker/mid360/livox-mid360:humble
GLIM単体docker/glim/glim-mapping:humble-cuda12.6
Localization単体docker/lidar-localization-mid360:humble
3機能収録オールインワンdocker/all-in-one/mid360-glim-localization:humble-cuda12.6

個別更新、障害分離、複数PCへの配置を重視する場合は独立構成を使う。初期評価や1台のGPU PCへの一括導入を重視する場合はオールインワンを使う。

14.2 共通前提

  • Docker EngineとCompose pluginを導入する。
  • GLIMを含む構成にはNVIDIA DriverとNVIDIA Container Toolkitが必要。
  • MID-360 UDPとROS 2 DDSのためLinux host networkを使用する。
  • 設定、地図、bagはイメージへ焼き込まずvolumeに保存する。
nvidia-smi
docker run --rm --gpus all ubuntu:22.04 nvidia-smi
アーキテクチャ: CUDA 12.6版GLIMの同梱DockerfileはUbuntu 22.04/x86_64向け。Jetson/arm64ではJetPack/L4Tに合うベースイメージとGLIM buildを別途用意する。

14.3 独立Dockerをbuildする

cd /path/to/ros2-materials/slam-localization-api/lidar_localization_ros2

# センサー
cd docker/mid360 && docker compose build

# GLIM
cd ../glim && docker compose build

# Localization
cd .. && docker compose build

各Composeはhost networkを使う。同一PCでは同じROS_DOMAIN_IDを設定することで、センサーの/livox/lidarと/livox/imuをGLIMまたはLocalizationから購読できる。

14.4 独立Dockerを起動する

# 端末1: MID-360
cd docker/mid360
docker compose run --rm --no-deps mid360 true
$EDITOR ~/mid360/config/MID360_config.json
docker compose up mid360

# 端末2: GLIM Mapping
cd docker/glim
docker compose run --rm --no-deps glim true
$EDITOR ~/glim/config/glim/config_ros.json
docker compose up glim

# または端末2でLocalization
cd docker
docker compose run --rm localization
GLIMとLocalizationを常に同時実行する必要はない。地図作成時はGLIM、作成済みPCDで自己位置推定するときはLocalizationを選ぶ。複数MID-360の点群を単純に同じtopicへ混ぜず、時刻同期・外部標定後の統合topicを使用する。

14.5 オールインワンをbuild・初期設定する

オールインワンは3機能を収録した1つのイメージであり、3機能同時実行という意味ではない。Compose serviceは用途が明確なmappingとlocalizationを用意する。

cd docker/all-in-one
mkdir -p ~/mid360_stack/config ~/ros_bags ~/ros2_maps
docker compose build

# GPUを要求せず設定ファイルを初期生成
docker run --rm \
  -v "${HOME}/mid360_stack/config:/data/config:rw" \
  mid360-glim-localization:humble-cuda12.6 true

$EDITOR ~/mid360_stack/config/MID360_config.json
$EDITOR ~/mid360_stack/config/glim/config_ros.json
$EDITOR ~/mid360_stack/config/localization.yaml
# localization.yamlのmap_pathを /data/maps/地図名.pcd に変更

14.6 オールインワンでリアルタイム処理する

xhost +local:docker

# MID-360 + GLIM: 地図作成
docker compose up mapping

# またはMID-360 + Localization: 既存地図で自己位置推定
docker compose up localization
排他的に選択: MappingとLocalizationは同時起動しない。地図を作るときはmapping、作成済み地図で自己位置を求めるときはlocalizationを実行する。

入力点群・IMU・TFを処理と同時にホストの~/ros_bagsへ保存する場合:

RECORD_BAG=true docker compose up mapping
# または
RECORD_BAG=true docker compose up localization

ホストにROS 2があればホスト側から同じtopicをrecordしてもよいが、上記ではコンテナ内のros2 bag recordを使うため、ホストへのROS 2導入は不要。

14.7 オールインワンでrosbagを再生する

# ホスト上のbagを確認
find ~/ros_bags -maxdepth 2 -name metadata.yaml -print

# bag + GLIM
INPUT_MODE=bag BAG_PATH=/data/bags/BAG_DIRECTORY \
  docker compose up mapping

# またはbag + Localization
INPUT_MODE=bag BAG_PATH=/data/bags/BAG_DIRECTORY \
  LOCALIZATION_RVIZ=true docker compose up localization

BAG_PATHはコンテナ内pathで指定する。bag modeではセンサードライバの代わりにコンテナ内でros2 bag play --clockを起動し、GLIMまたはLocalizationへuse_sim_time=trueを渡す。ホスト側で別途playする必要はない。

14.8 オフライン配布

# 例: 4イメージを保存
for image in \
  livox-mid360:humble \
  glim-mapping:humble-cuda12.6 \
  lidar-localization-mid360:humble \
  mid360-glim-localization:humble-cuda12.6
do
  file=$(echo "$image" | tr '/:' '__').tar.gz
  docker save "$image" | gzip > "$file"
  sha256sum "$file" > "$file.sha256"
done

# 配布先では各ファイルを検証してload
sha256sum -c IMAGE_FILE.tar.gz.sha256
gunzip -c IMAGE_FILE.tar.gz | docker load

使用する構成のcompose.yaml、イメージtar.gz、SHA-256ファイルを一緒に配布する。作成側と配布先のCPUアーキテクチャを合わせ、GLIM構成の配布先ではNVIDIA DriverとContainer Toolkitを別途準備する。

14.9 Jetson・Qualcomm系arm64ボード

arm64では構成ごとの対応範囲が異なる。MID-360センサー単体とLocalization単体は、Ubuntu 22.04を実行するボード上でnative buildする。使用イメージがarm64/linuxになったことをdocker image inspectで確認する。

# Jetson / Qualcomm共通: センサー
cd docker/mid360
docker compose build --pull
docker image inspect livox-mid360:humble \
  --format '{{.Architecture}}/{{.Os}}'

# Localization
cd ..
docker compose build --pull localization
docker image inspect lidar-localization-mid360:humble \
  --format '{{.Architecture}}/{{.Os}}'
GLIMの扱い: 同梱GLIMおよびオールインワンDockerfileはx86_64用CUDA repositoryを使うためarm64では停止する。Jetson版はJetPack/L4Tと一致するbase image上で依存ライブラリとGLIMをsource buildして実機検証する必要がある。QualcommのAdreno/HexagonはCUDA互換ではないため、Mappingをx86_64 CUDA PCへ分離し、Qualcomm側はセンサー受信・bag収録・Localizationを担当させる。

JetPack/Container Runtimeの確認、Qualcomm BSPの前提、headless運用、分散Mapping、arm64イメージ配布の詳細はJetson・Qualcomm系arm64手順を参照する。

14.10 実機投入前チェック

docker compose config
ros2 topic type /livox/lidar  # sensor_msgs/msg/PointCloud2
ros2 topic type /livox/imu

コンテナ化はセンサーIP、TF、時刻同期、外部標定、ROS_DOMAIN_ID、地図pathの不一致を自動解決しない。実機またはbagで構成ごとに確認する。
