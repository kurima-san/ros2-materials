14. Docker環境の作成・配布

同梱ファイル: Dockerfile、compose.yaml、短縮手順。4章と同じ修正版CMakeをイメージのbuild中に適用する。

14.1 前提と設計

  • ホストへDocker EngineとCompose pluginを導入済みにする。
  • MID-360のUDPと他のROS 2ノードを見つけやすくするためLinuxのhost networkを使用する。
  • 地図とrosbagはイメージへ焼き込まずvolumeで永続化する。
  • GUIはX11を共有する。Wayland専用環境やmacOS/Windowsでは別途X serverが必要。
対応CPUを確認: 通常のbuildで作るイメージはbuildしたCPU向け。Jetson（arm64）へ持ち込むならJetson/arm64環境でbuildするか、buildxでarm64を指定して実機検証する。amd64イメージをそのままJetsonでは実行できない。

14.2 イメージを作る

cd /path/to/ros2-materials/slam-localization-api/lidar_localization_ros2/docker
docker compose build
docker image inspect lidar-localization-mid360:humble

14.3 起動と確認

mkdir -p ~/ros2_maps ~/ros_bags
xhost +local:docker  # RVizを使うLinuxホストだけ
docker compose run --rm localization

# コンテナ内
ros2 pkg prefix lidar_localization_ros2
ros2 pkg executables lidar_localization_ros2

地図は/data/maps、bagは/data/bagsを参照する。終了後、必要ならホストでxhost -local:dockerとして許可を戻す。

14.4 USB等で別PCへオフライン導入

# 作成PC
docker save lidar-localization-mid360:humble | gzip > lidar-localization-mid360_humble.tar.gz
sha256sum lidar-localization-mid360_humble.tar.gz > lidar-localization-mid360_humble.tar.gz.sha256

# 上の2ファイルと docker/compose.yaml を対象PCへコピー後
sha256sum -c lidar-localization-mid360_humble.tar.gz.sha256
gunzip -c lidar-localization-mid360_humble.tar.gz | docker load
docker compose -f compose.yaml run --rm localization

14.5 Registry経由で導入

# 作成PC（例。実際のregistry名へ置換）
docker tag lidar-localization-mid360:humble registry.example.com/robot/lidar-localization:humble
docker push registry.example.com/robot/lidar-localization:humble

# 対象PC
docker pull registry.example.com/robot/lidar-localization:humble
docker tag registry.example.com/robot/lidar-localization:humble lidar-localization-mid360:humble
docker compose -f compose.yaml run --rm localization
再現性: build日、Git commit、CPUアーキテクチャ、docker image inspectのimage ID／RepoDigest、配布ファイルのSHA-256を記録する。公開済みイメージを使う場合も、提供元、対応ROS distroとCPU、更新日を確認しdigestで固定してから実データで検証する。

14.6 実機投入前チェック

docker run --rm lidar-localization-mid360:humble \
  bash -lc 'ros2 pkg prefix lidar_localization_ros2'
docker compose config

その後、7章または8章の手順でtopic、TF、時刻、地図pathを確認する。コンテナ化はセンサー校正、TF、ROS_DOMAIN_IDの不一致を自動的には解決しない。
