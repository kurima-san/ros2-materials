3. GLIM セットアップ・マップ作成

今回の推奨: Ubuntu 22.04 + CUDA 12.6 なら、GTSAM / gtsam_points / GLIMを個別にsource buildせず、Koide公式PPAのCUDA 12.6版を使います。

GLIM v1.2.2はGTSAM 4.3a1関連の修正も含み、Ubuntu 22.04/24.04、CUDA 12.2/12.6/13.1でテストされています。

3.1 NVIDIA / CUDA確認

nvidia-smi
nvcc -V
readlink -f /usr/local/cuda 2>/dev/null || true
以前source buildした /usr/local/lib/libgtsam* とPPA版を混在させると、ABI違いによるundefined symbolの原因になります。PPA運用とsource運用は混ぜないでください。
ldconfig -p | grep -E 'gtsam|gtsam_points'
ls -l /usr/local/lib/libgtsam* /usr/local/lib/libgtsam_points* 2>/dev/null || true

3.2 Koide PPA

sudo apt update
sudo apt install -y curl gpg
curl -s https://koide3.github.io/ppa/setup_ppa.sh | sudo bash

sudo apt update
sudo apt install -y   libiridescence-dev   libboost-all-dev   libglfw3-dev   libmetis-dev   libgtsam-points-cuda12.6-dev   ros-humble-glim-ros-cuda12.6

sudo ldconfig

3.3 GLIM設定

GLIMは config_ros.json でpoints/IMU topicを指定します。パッケージ内設定を直接編集するより、 ローカルconfigをコピーして config_path で絶対パス指定すると管理しやすいです。

mkdir -p ~/glim_config
cp -r /opt/ros/humble/share/glim/config/* ~/glim_config/ 2>/dev/null || true

# config_ros.json の例
# "imu_topic": "/livox/imu"
# "points_topic": "/livox/lidar"
実際のインストール先は ros2 pkg prefix glim / ros2 pkg prefix glim_ros で確認してください。

3.4 GLIMへ渡す前に同行者・近距離点を除外

センサを持つ人とPCを持つ人が一緒に歩き、 PCを持つ人がMID-360に対してほぼ同じ相対位置にいた場合、 LiDAR座標系ではその人がほぼ静止して見える。 そのため一般的な「動いた点を削除」より、 センサ座標系で既知の領域を常時除外する方が確実。

/livox/lidar
     ↓
mid360_mapping_filter.py
     ├─ min_range
     ├─ self exclusion box
     └─ companion exclusion box
     ↓
/livox/lidar_mapping
     ↓
GLIM

フィルタファイル

tools/mid360_mapping_filter.py
tools/run_mid360_mapping_filter_example.sh

1. 最短距離

全方向の球状フィルタ。センサ直近の手、腕、取付治具などを落とす。

-p min_range_m:=0.50
0.50 mは開始例でありMID-360のハードウェア最短距離設定ではない。 必要な壁や床まで消えない範囲をRVizで確認して決める。 同行者が1 m前後にいる場合、最短距離だけでは人物は消えない。

2. 同行者領域

同行者がセンサに対して一定位置を歩く場合は直方体で除外する。

-p companion_box_enabled:=true \
-p companion_min_x:=-1.5 \
-p companion_max_x:=0.5 \
-p companion_min_y:=-1.5 \
-p companion_max_y:=-0.3 \
-p companion_min_z:=-1.5 \
-p companion_max_z:=1.0
上の座標は例。 実際の同行者が右・左・後ろのどこを歩いていたかで値は変わる。 RVizで Fixed Frame=livox_frame として生点群を表示し、 同行者のx/y/z範囲を確認してから設定する。

3. センサ保持者自身

MID-360を手で持つ場合、保持者の胸・脚・腕が一定領域に入り続けることがある。 必要なら別の self_box を有効にする。

-p self_box_enabled:=true \
-p self_min_x:=-0.4 \
-p self_max_x:=0.4 \
-p self_min_y:=-0.4 \
-p self_max_y:=0.4 \
-p self_min_z:=-1.8 \
-p self_max_z:=-0.1

これも例。センサの持ち方に合わせて決める。

4. 起動

source /opt/ros/humble/setup.bash
source ~/livox_ws/install/setup.bash

python3 /path/to/guide/tools/mid360_mapping_filter.py --ros-args \
  -p input_topic:=/livox/lidar \
  -p output_topic:=/livox/lidar_mapping \
  -p min_range_m:=0.50 \
  -p companion_box_enabled:=true \
  -p companion_min_x:=-1.5 \
  -p companion_max_x:=0.5 \
  -p companion_min_y:=-1.5 \
  -p companion_max_y:=-0.3 \
  -p companion_min_z:=-1.5 \
  -p companion_max_z:=1.0

5. RVizで生点群と比較

PointCloud2 A: /livox/lidar
PointCloud2 B: /livox/lidar_mapping
Fixed Frame: livox_frame

同行者だけが消え、壁・床・柱など必要な静的構造が残るようにboxを調整する。

6. GLIMの入力を変更

config_ros.json のpoints topicを:

"/livox/lidar"

から:

"/livox/lidar_mapping"

へ変更してからGLIMを実行する。

PointCloud2のtimestampフィールドも保持する。 同梱フィルタは選択した点の元PointCloud2レコードをそのままコピーするので、 Livox固有の intensity/tag/line/timestamp を落とさない。

7. 最長距離

遠距離ノイズやmapping対象外を切りたい場合だけ:

-p max_range_m:=50.0

0.0なら無効。建物規模に合わせて設定する。

3.5 リアルタイムMapping

source /opt/ros/humble/setup.bash
source ~/livox_ws/install/setup.bash

ros2 run glim_ros glim_rosnode   --ros-args -p config_path:=$(realpath ~/glim_config)

3.6 rosbagからMapping

glim_rosbag はbagを直接読み、データdropを避けながら再生速度を調整します。

ros2 run glim_ros glim_rosbag ~/workspace/ros_bag/atr_out   --ros-args -p config_path:=$(realpath ~/glim_config)

3.7 Mapping結果

標準では終了時に /tmp/dump にmapping dumpが保存されます。

ros2 run glim_ros offline_viewer

File → Open Map でdumpを開き、必要ならloop constraint等を修正後、 File → Save → Export Points で点群をPLYとして出力します。

3.8 PLY → PCD

sudo apt install -y pcl-tools

pcl_ply2pcd atr_out_points.ply atr_out_points.pcd

生成したPCDを:

~/ros2_ws/src/lidar_localization_ros2/map/atr_out_points.pcd

などに置き、Localization YAMLの map_path と一致させます。

Source buildが必要な場合

公式にはGTSAM → Iridescence → gtsam_points → GLIM/glim_ros2の順でsource buildする手順もあります。 ただし今回の環境では以前GTSAMの版混在が発生したため、特別な改造が必要でない限りPPAを優先します。
